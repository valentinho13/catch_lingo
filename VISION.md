# CatchLingo Vision

## Elevator Pitch

CatchLingo helps people learn languages from the real world around them.

The user opens the app, points the camera at things they actually see, and CatchLingo helps turn those real-world objects into vocabulary.

The goal is not to study random word lists.

The goal is to make the world itself become the vocabulary source.

## Core Idea

The user enters Explore Mode.

They walk through a room, a city, a market, a hotel, a restaurant, a train station, or a travel destination.

They point the camera at objects, signs, products, food, animals, vehicles, tools, furniture, and places.

CatchLingo detects interesting words, shows them in the target language, and stores them for later review.

Example:

- chair → kursi
- table → meja
- bottle → botol
- motorcycle → sepeda motor
- coffee → kopi

The app should feel like:

> Point your camera at the world. Discover the words that live there.

## Product Positioning

CatchLingo is not primarily:

- a dictionary
- a translator
- a school app
- a flashcard app
- a technical object-detection demo
- a generic vocabulary manager

CatchLingo is:

> a real-world language discovery tool.

The camera is the bridge between real life and vocabulary.

The user should not feel like they are studying.

The user should feel like they are noticing language in the world.

## Core Product Promise

CatchLingo should answer this feeling:

> “I saw this thing in real life. Now I know the word for it.”

That is the emotional core.

The word matters because the user encountered it.

The app should connect vocabulary to:

- place
- situation
- memory
- travel
- everyday life
- curiosity
- real-world context

## Core Loop

The core loop is:

1. Explore the real world
2. Detect interesting objects or labels
3. Catch the word
4. Celebrate the discovery
5. Save it to the personal dictionary
6. Review it later
7. Explore again

Short version:

> Discover → Catch → Remember

## Product Feeling

CatchLingo should feel:

- lightweight
- modern
- playful
- useful
- visual
- travel-friendly
- fast
- personal
- curious

It should not feel:

- academic
- childish
- overloaded
- like homework
- like a language course
- like an ML demo
- like a dense dashboard

## The World Is the Textbook

Most language-learning apps start with prepared vocabulary.

CatchLingo starts with the user’s surroundings.

A hotel room becomes vocabulary.
A street market becomes vocabulary.
A restaurant table becomes vocabulary.
A vacation becomes vocabulary.
A commute becomes vocabulary.

The user learns words they actually encounter.

This makes vocabulary more memorable because it is tied to real situations.

## Target Use Cases

### Travel

The user is in Indonesia, Japan, France, Spain, or any travel destination.

They point the camera at real things around them and build a vocabulary collection from that trip.

Example:

- airport
- motorcycle
- market
- rice
- bottle
- chair
- receipt
- hotel
- beach
- taxi

### Everyday Learning

The user walks around their home or city and discovers common words.

Example:

- door
- window
- cup
- lamp
- street
- tree
- bus

### Casual Curiosity

The user sees something and wonders:

> “What is this called in the language I’m learning?”

CatchLingo should make that moment quick and satisfying.

## Collection Philosophy

The collection exists because the world produced the words.

This is not card collecting for its own sake.

Words are collected because they were discovered in context.

A collected word should feel like:

> a memory from a real-world moment

not:

> an item in a school vocabulary list.

## Explore Mode

Explore Mode is the heart of CatchLingo.

The user points the camera at the world.

The app detects possible words and offers them as catchable discoveries.

Explore Mode should eventually support:

- camera preview
- detected object labels
- word chips
- target-language translation
- tap-to-catch
- optional auto-catch
- session counter
- collection feedback
- session summary

For the MVP, camera behavior can be simulated with mock detections.

The MVP must still feel like a preview of the future camera experience.

## Dictionary Mode

The Dictionary is the user’s personal word memory.

It stores the words the user has caught from the real world.

It should feel personal, simple, and useful.

It should not feel like an endless vocabulary database.

Dictionary entries should eventually include:

- target word
- source meaning
- category
- caught date
- session
- optional place/travel context
- learned status
- review status

## Review Mode

Review Mode helps the user remember caught words.

It should be light and simple.

Flashcards are useful, but they are not the product’s identity.

Review exists to support the real-world discovery loop.

## Anti-Homework Rule

CatchLingo must never feel like homework.

Whenever there is a choice between:

- more educational structure
- more curiosity and discovery

prefer curiosity and discovery, unless learning quality would clearly suffer.

The app should make users want to open it.

Not because they feel guilty.

Because they are curious.

## Anti-Demo Rule

CatchLingo must never feel like a technical demo.

The user should not think:

> “This app detects objects.”

The user should think:

> “This app helps me discover words around me.”

Object detection is just the tool.

The real product is the experience.

## Long-Term Vision

One day, CatchLingo could support:

- real camera detection
- multiple target languages
- travel sessions
- location-based memory
- review reminders
- pronunciation
- example sentences
- AI-assisted explanations
- personalized discovery suggestions

But the core must remain simple:

> Point. Discover. Catch. Remember.

## Product Principle

The user should feel:

> “I discovered this word in the real world.”

Not:

> “I completed another lesson.”

Not:

> “I added a vocabulary item.”

CatchLingo should make language feel visible in everyday life.
